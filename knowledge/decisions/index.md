# Decisions

* [External workspace state and the Clearhead boundary](external-workspace-and-clearhead-boundary.md) - Keeps dynamic workspace state external and defines Clearhead and Agent Workspace as sibling authorities.
* [Center the tool surface on MCP](mcp-centered-tool-surface.md) - Makes MCP the canonical workspace tool surface and Pi a thin MCP client plus read-capture hook.
* [Use OKF for curated project knowledge](okf-curated-knowledge-layer.md) - Separates durable shared project knowledge from situated workspace state by temporality and authority, while the workspace provides a unified harness-neutral orientation over both.
* [Biome as the canonical TypeScript formatter, enforced at commit](typescript-formatter-gate.md) - Adopts pinned Biome (formatter-only) as canonical form for the Pi extension TypeScript and enforces it in the pre-commit gate, mirroring the rustfmt discipline.
* [MCP servers resolve their repository from the launch directory and fail loud when it is wrong](mcp-repository-resolution.md) - MCP servers use repository-relative paths in .mcp.json (not the unreliable ${CLAUDE_PROJECT_DIR}), and the server names a missing repository instead of dying with an opaque I/O error.
* [Claims gain a retirement disposition: retire without a replacement](claim-retirement-disposition.md) - Adds a ClaimRetired event and ClaimLifecycle::Retired variant so a claim can be retired without a successor, giving claims the freshness-orthogonal disposition axis findings already have and unclogging the stale signal.
* [Sequence freshness-cost work: diff-on-stale, then drift instrumentation, then relocatable selectors](freshness-cost-sequencing.md) - Defers the relocatable exact-text selector proposal behind diff-on-stale and a pure drift-frequency diagnostic, so trust-critical reconcile machinery is built only after the coordinate-drift cost is measured.
* [Durable constraints are a portable intent entity, distinct from claims](durable-constraints-portable-intent-entity.md) - Defines thin repo-scoped constraint and knowledge bindings; the 2026-09-15 cold probe fired the friction gate for contract work while preserving external canonical knowledge and a bare-repository fallback.
* [Coordination pilot before build-out, and documented trust limits](coordination-pilot-and-trust-limits.md) - Records owner decisions to pilot coordination with existing tools after contextual freshness, require a bounded reliance measurement before new coordination entities, and document attribution and capture-integrity limits.
* [Worktree-relative freshness](worktree-relative-freshness.md) - Makes claim/evidence/finding verdicts worktree-relative by stamping a worktree identity on assessment events and materializing the querying worktree's verdict during replay, without a separate assessment entity.
* [Selection disposition — existing tools suffice; the substrate is the intentions board, linked not built-in](coordination-selection-disposition.md) - Coordination-selection outcome (2026-09-14): no explicit coordination machinery in code or guidance and no explicit dependency on the Clearhead CLI; workstreams-sessions build-out cancelled with its gap narrowed to the orientation-worktree-context fix; declarations and handoff cancelled as existing tools sufficed; dogfood re-scoped; Clearhead updates applied as a projection of this record.
* [Charter plural agency as a falsifiable research program](plural-agency-charter-transition.md) - The owner authorizes a research-only plural-agency charter, stages its first matched falsification trial behind knowledge-continuity dogfood, and replaces the obsolete swarm-dogfood obligation without reopening cancelled coordination machinery.
* [Harness session logs are a separate authority, joined to workspace state by session identity](session-log-observability.md) - Observes proprietary harnesses by archiving and normalizing their own session files outside the kernel, keeps live read capture in hooks, shares per-harness payload fixtures instead of parsing code, and joins the two sources on (host, harness, session) for offline analysis.
